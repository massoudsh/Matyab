# معماری فنی

## نمای کلی
```
┌──────────────┐      HTTPS/REST      ┌───────────────┐
│   Frontend   │ ───────────────────▶ │    Backend    │
│  (Next.js)   │ ◀─────────────────── │ (Express/TS)  │
└──────────────┘                      └───────┬───────┘
                                               │
                 ┌─────────────────────────────┼─────────────────────┐
                 ▼                             ▼                     ▼
          ┌─────────────┐              ┌──────────────┐      ┌──────────────┐
          │ PostgreSQL  │              │    Redis     │      │  Object      │
          │ (+pgvector) │              │ (کش/صف)      │      │  Storage(S3) │
          └─────────────┘              └──────────────┘      └──────────────┘
                 ▲
                 │  توسط ماژول‌های داخلی backend مصرف می‌شود:
        ┌────────┴─────────┬──────────────────┬──────────────────┐
        ▼                  ▼                  ▼                  ▼
  Quality Scoring    Price Suggestion    Matching Engine    Shipping Calculator
  (تحلیل عکس)        (تاریخچه‌ی قیمت)     (rule + vector)   (فاصله‌ی جغرافیایی)
```

## لایه‌ها

### Frontend
- Next.js 14 (App Router)، TypeScript، TailwindCSS، پشتیبانی کامل RTL فارسی.
- صفحات اصلی: آگهی‌های عرضه، درخواست‌های تقاضا، match های پیشنهادی، داشبورد پروژه.

### Backend
- Node.js + TypeScript + Express (سبک، بدون فریم‌ورک سنگین در فاز MVP).
- Prisma ORM برای دسترسی به PostgreSQL.
- ماژول‌بندی بر اساس دامنه (auth، listings، requests، matching، pricing، quality، shipping، transactions).
- لایه‌ی AI به‌صورت service جدا داخل backend نوشته می‌شود؛ در فازهای بعدی می‌تواند به microservice مستقل جدا شود (مثلاً برای پردازش تصویر سنگین).

### دیتابیس
- PostgreSQL به‌عنوان منبع اصلی truth.
- افزونه‌ی `pgvector` برای نگه‌داری embedding توضیحات/تصاویر مصالح جهت مچینگ معنایی (نه فقط دسته‌بندی دستی).
- Redis برای کش قیمت‌های پیشنهادی و صف پردازش تصویر (quality scoring async).

### ذخیره‌سازی فایل
- عکس‌های مصالح در object storage سازگار با S3 نگه‌داری می‌شود؛ فقط URL در دیتابیس ذخیره می‌شود.

## نکات مهم پیاده‌سازی
- **بدون پرداخت آنلاین در MVP** — فقط اتصال دو طرف؛ تراکنش واقعی خارج از پلتفرم انجام می‌شود تا اعتماد اولیه شکل بگیرد.
- **AI به‌صورت پیشنهاد، نه تصمیم قطعی** — همیشه به کاربر «چرا این پیشنهاد» نشان داده می‌شود (شفافیت تصمیم).
- **مقیاس‌پذیری منطقه‌ای** — طراحی داده از ابتدا بر اساس `region`/`city` است تا گسترش جغرافیایی ساده باشد.
