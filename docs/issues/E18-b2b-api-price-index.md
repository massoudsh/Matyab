# Epic 18 — اشتراک B2B، API عمومی و شاخص قیمت منطقه‌ای
لیبل: `epic`, `v2`, `backend`, `frontend`

مسئله (روادمپ فاز ۳): مدل درآمدی فعلی فقط کمیسیون تراکنشی است. تأمین‌کنندگان/انبارهای بزرگ ارزش بیشتری
از دسترسی API و اولویت در جست‌وجو می‌گیرند؛ و داده‌ی قیمتی جمع‌شده (`PriceHistory`) خودش یک محصول اطلاعاتی
مستقل می‌تواند باشد («شاخص قیمت مصالح دست‌دوم»).

---
### ISSUE-1801: مدل داده‌ی اشتراک B2B
**معیار پذیرش:**
- [ ] فیلدها روی `Supplier`/`User`: پلن (`FREE`/`B2B`)، تاریخ انقضا
- [ ] محدودیت نرخ درخواست (rate limit) بر اساس پلن روی API عمومی

---
### ISSUE-1802: API Key و دسترسی برنامه‌نویس
**معیار پذیرش:**
- [ ] `POST /developer/api-keys` (فقط کاربران B2B)
- [ ] میدل‌ور احراز هویت با API Key به‌جای JWT برای مسیرهای عمومی (`/public/*`)

---
### ISSUE-1803: اولویت در جست‌وجو برای تأمین‌کنندگان B2B
**معیار پذیرش:**
- [ ] `compareSuppliers` و لیست Listings، نتایج تأمین‌کننده/فروشنده‌ی B2B را با نشان مشخص در ابتدای لیست نشان دهد (نه حذف رقبا، فقط اولویت نمایش)

---
### ISSUE-1804: شاخص قیمت منطقه‌ای مصالح دست‌دوم
**شرح:** خروجی عمومی/دوره‌ای از `PriceHistory` تجمیع‌شده به تفکیک دسته و شهر — مشابه شاخص قیمت مسکن.
**معیار پذیرش:**
- [ ] `GET /public/price-index?categoryId=&city=` — میانگین/میانه‌ی قیمت هفتگی
- [ ] صفحه‌ی عمومی نمایش نمودار روند قیمت (بدون نیاز به لاگین)

---
### ISSUE-1805: مستندسازی API عمومی
**لیبل:** `frontend`
**معیار پذیرش:**
- [ ] صفحه‌ی `/developers` با مثال درخواست/پاسخ برای `price-index` و لیست Listings عمومی
